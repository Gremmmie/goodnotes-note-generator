# Web Chat Handoff（网页端交接）

当出图这一步发生在**网页端 ChatGPT**（或任何读不到本地路径的浏览器 AI）时，用本文件规定的交接方式。

核心分工：**本地负责内容与规格，网页端只负责渲染成手写风笔记图。**

## 1) 何时进入网页端模式

命中任一条就走这里：

- 用户说"要用网页端/ChatGPT 网页版出图""网页端读不到我的文件""我把资料发给网页版让它画"。
- 用户要给的是本地 PDF／论文／课件／截图／长文，而渲染发生在本机之外的浏览器里。
- 用户要复现同一套笔记图，但生成环境无法访问本地目录。

不命中时（本地就能出图）走 SKILL.md 的常规流程，不生成交接包。

## 2) 交接包结构

默认输出到源文件同级的 `web_handoff/`（目录已存在且非空时自动改用 `web_handoff_2`、`web_handoff_3`，不覆盖）：

```
web_handoff/
├── pages/                 # 可直接上传的页面图（PNG，超限时降级为 JPEG）
│   ├── <来源>-p01.png
│   └── <来源>-p02.png
├── context_pack.md        # 带来源文件名与页码的文本摘录（不含本地路径，可直接上传）
├── upload_manifest.md     # 上传清单：Priority / 文件名 / 本地路径 / 大小 / 用途 / 准备
├── web_prompt.md          # 由 agent 撰写的粘贴用 prompt（不做成模板文件）
└── handoff.json           # 机器可读摘要，供 agent 与后续复用读取
```

机械转换（渲染、缩放、体积控制、清单、文本抽取）交给 `scripts/render_upload_pages.py`；
`web_prompt.md` 必须由 agent 依清单与 `context_pack.md` 撰写，脚本不生成它。

**可上传与不可上传**：`pages/` 与 `context_pack.md` 可以上传（`context_pack.md` 刻意不含本地绝对路径）；
`upload_manifest.md` 与 `handoff.json` **含本地绝对路径，仅供本地使用，绝不粘贴或上传给网页端**。

```bash
python3 scripts/render_upload_pages.py <来源文件...> \
  [--out DIR] [--max-files 5] [--max-mb 5] [--long-edge 2000] [--force]
```

## 3) 两种传递形态

| 形态 | 适用 | 网页端拿到什么 |
| --- | --- | --- |
| 页面图包（默认） | 源材料是版式重要的 PDF／课件／扫描件，或需要网页端自己看原文 | 上传 `pages/*.png`，靠多模态读图 |
| 文本交接包 | 源材料是纯文本，或已由本地锁定逐页精确文案 | 只粘贴 `web_prompt.md`（内含每页要渲染的原文案） |

两种都产出时，在 `web_prompt.md` 里明确说明"上传的图只是素材来源，不要直接复用页面版式"。
网页端无法加载本地图片路径——**绝不要在 prompt 里写本地绝对路径**，只写上传后的文件名。

## 4) `web_prompt.md` 的固定结构

按下面七段写，祈使句，可整段复制：

1. **角色与证据边界**：声明网页端只能依赖本 prompt 与已上传文件，读不到任何本地路径；缺资料时点名要哪一份，不要臆造。
2. **出图目标**：要几张、竖版 3:4、用途（小红书等分享平台）、成功标准（一眼能读懂、可单独成图）。
3. **每页计划**：一页一个主题；每页写清 `页号 / 主题 / 页面原型（A–F，见 output-patterns.md）/ 要出现的分栏结构`。
4. **视觉规范**：纯白底；黑色或深灰正文；四色 `#005087` / `#86B8CE` / `#B23939` / `#D88080` 只用于标题、下划线、标签、强调；中英混排手写感；手绘箭头、括号、圈注、简笔示意。
5. **每页精确文案**：逐页给出要渲染的中文与英文原文，标注哪些术语必须原样保留。这是网页端最需要的部分——**文案由本地锁定，不让网页端自行改写**。
6. **禁止项**：海报感、满版密排、渐变与阴影、系统字体的整齐正文、把整段原文照抄上页、页面四边填满。
7. **输出要求**：逐页给图；保持跨页一致的版式与配色；如某页信息装不下，先说明再拆页，不要缩小字号塞入。

## 5) 上传预算与降级

默认预算：**≤ 5 个文件、单文件 ≤ 5 MB、图片长边 ≤ 2000 px**。用户给了具体上限就以其为准。

超预算时按此顺序降级，不要直接放弃：

1. 合并同源页：把连续的同一主题页合成一张长图或拼图。
2. 降分辨率：脚本会按 0.85 / 0.72 / 0.6 逐级缩放，仍超限才转 JPEG。
3. 只传关键页：优先传承载"每页精确文案"依据的页，其余靠 `context_pack.md` 的文本补齐。
4. 超出的页在清单里显式标注"未纳入本包"及原因，并在 `Before sending` 里说明需要二次交接。

## 6) 不该上传

沿用 `web-ai-handoff` 的安全边界：密钥与凭据、`.env`、私钥、未公开或受限数据、含个人信息的附件一律不进包；需要引用时用脱敏替代文本，并在清单的 `do not upload` 行里记录。

通用交接规则（context pack 写法、上传清单字段、机密判定）**只引用 `web-ai-handoff` skill，不在本文件重写**，避免双源冲突；本文件只补"出图场景"特有的部分。

## 7) 质检清单

交付前逐条确认：

- `web_prompt.md` 里没有任何本地绝对路径，只有上传文件名。
- 每页的精确文案都已写死在 prompt 里，网页端无需自行改写内容。
- 上传文件数与体积在预算内；超出的页已在清单里说明。
- 每页标注了页面原型，且一页一个主题。
- 视觉规范段落包含白底、3:4、四色、手写感、手绘元素五项。
- 禁止项已列出，且与 `visual-style.md` 的"避免"清单一致。
- 敏感材料未被列入上传清单。

## 8) 常见故障与修法

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 网页端说"看不到你的文件" | prompt 里写了本地路径，或没上传 | 改成"已上传的 `xxx.png`"，并核对清单 |
| 中文被渲染成规整系统字体 | 未强调手写感与"非系统字体" | 在视觉规范与禁止项两处同时点明 |
| 页数或分页跑偏 | 未给每页计划 | 在 prompt 第 3 段补齐页号—主题—原型 |
| 文字被网页端自己改写／丢术语 | 未锁定精确文案 | 第 5 段逐页给出原文，并标注须原样保留的术语 |
| 单页信息过密 | 一页塞了两个主题，或源材料过密 | 拆页，不要缩字号；必要时走"只传关键页"降级 |
| 上传被拒（超体积） | 页面图过大 | 减小 `--long-edge` 或 `--max-mb` 重跑脚本 |
| 图风跨页不一致 | 未在 prompt 里要求跨页一致 | 第 7 段加"跨页保持一致版式与配色" |
